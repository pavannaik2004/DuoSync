# Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed MERN skeleton where players sign up, log in, create a 2-player team and join it with an invite code (PRD §11 Phase 1).

**Architecture:** An Express 5 app built by `createApp()` in MVC folders (routes → controllers → services → models), with JWT bearer auth and one central error handler. A Vite React client uses React Router, an `AuthContext` and a small fetch wrapper. Tests cover the backend only (Jest + Supertest + mongodb-memory-server), as the PRD requires.

**Tech Stack:** Node 22, Express 5, Mongoose, express-validator, bcryptjs, jsonwebtoken, helmet, cors, express-rate-limit, dotenv; React 19 + Vite, react-router-dom, prop-types; Jest, Supertest, mongodb-memory-server.

**Spec:** `PRD Collaborative Digital Escape Room.md`. Cross-phase decisions are in `docs/superpowers/plans/2026-11-09-00-roadmap.md`, and every choice the PRD left open is logged in `DECISIONS.md`. Read all three before starting.

**PRD requirements covered:** AUTH-1, 2, 3 (token only; practice comes later), 4, 5; TEAM-1, 2, 3 (without challenge record), 4, 5, 6 (members only); NFR-2, 5, 6, 19, 20 (partial); UI-1 pages for this phase.

## Global Constraints

- **Workflow:** before starting any task, read `CONTEXT.md`. After finishing it, append a dated log entry to `CONTEXT.md` (what was done, files, test result). Record every new or deferred decision in `DECISIONS.md`.
- **Commits:** no `Co-Authored-By` trailer and no mention of Claude in commit messages or PR bodies.
- JavaScript only: `.js` on the server (CommonJS `require`), `.jsx` for React. No TypeScript.
- No CSS framework or component library. Plain CSS with custom properties on `:root`.
- Passwords: bcrypt (via `bcryptjs`), cost **10**. Token expiry: **7d** for accounts, **24h** for guests (NFR-2).
- Login and signup: at most **10 requests per minute per IP** (NFR-6). Set `app.set('trust proxy', 1)` so this works behind Render's proxy.
- Username `/^[A-Za-z0-9_]{3,20}$/`. Password: at least 8 characters with a letter and a digit, `/^(?=.*[A-Za-z])(?=.*\d).{8,72}$/` (72 is bcrypt's limit). Team name: 3–24 characters (AUTH-1, TEAM-1). These regexes appear in both `server/src/utils/patterns.js` and `client/src/utils/validators.js` and must stay identical.
- Invite code: **8** characters (TEAM-1), from the roadmap alphabet.
- Error body: `{ error, message }` with the right HTTP status (NFR-20).
- No raw request objects in queries: every value that reaches Mongoose is a validated string (NFR-5).
- Must work at 360 px width with no horizontal scroll, and touch targets of at least 44 px (NFR-15).

## Review Focus

1. **Two players join the last team slot at the same moment.** Exactly one succeeds and the other gets 409 `TEAM_FULL`. A team never has 3 members. Test in Task 5.
2. **A malformed id in a URL** (`/api/teams/abc`, `/members/xyz`) returns a 404 JSON error, never a 500 or a leaked CastError. Test in Task 4.
3. **An object posted where a string is expected** (`{ "email": { "$ne": null } }`) returns 400 `VALIDATION_ERROR` and never logs anyone in. Test in Task 2.
4. **The captain leaves while the partner stays.** The partner becomes captain and the team stays active. When the last member leaves, the team is archived and its invite code stops working. Test in Task 6.
5. **An off-site `?next=` after login** (`//evil.com`, `https://evil.com`) is ignored and the user lands on `/dashboard`. `safeNext()` in Task 8, with a manual check step (there are no frontend tests, per the PRD).

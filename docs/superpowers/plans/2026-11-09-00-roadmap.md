## Cross-phase decisions

**API conventions (Phase 1, used everywhere)**
- Every error body is `{ error: CODE, message }`, plus `details: [{ field, message }]` for validation (NFR-20). Codes are SCREAMING_SNAKE strings that the client switches on, never on `message`.
- Services throw `AppError(status, code, message)`; one `errorHandler` maps it. Mongoose `CastError` → 404 of the resource; duplicate key 11000 → 409.
- Auth: `Authorization: Bearer <jwt>`. Payload `{ sub, kind: 'user' | 'guest', nickname? }`. Roles are **not** in the token; `requirePlayer` loads the user from the DB on every request so a role grant (ADMIN-6) applies right away.
- Middleware chain names: `requireAuth` (user or guest), `requirePlayer` (user only, sets `req.user`), `requireRole('admin' | 'organizer')`. The socket handshake (Phase 2) reuses `verifyToken(token)` from `services/tokenService.js`.
- Codes come from `services/codeService.js`: `generateCode(length)` over the alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` with `crypto.randomInt`. Team invite = 8, challenge = 6, practice room = 6. A Mongoose setter uppercases every stored code (§10.1 Unit III).

**Attempt engine (Phase 2, extended in 3–4)**
- Practice rooms and challenge attempts are the same `Attempt` document. `challengeId` is null for practice, and `practiceCode` is set instead. Phase 2 plays Cyber Heist through a minimal practice room (`POST /api/practice`, join by code), because challenges arrive only in Phase 3. Phase 5 adds guest access, expiry and polish (PRAC-1..4).
- Live attempts run in process: `AttemptRuntime` instances are kept in a `Map<attemptId, runtime>`. Each runtime owns a promise queue (`runtime.enqueue(fn)`) that serializes every mutating socket event (GAME-7, NFR-9), plus the 1 s tick interval (a closure, §10.1 Unit I). Solves also use an atomic conditional update (`levels.$.solvedAt: null` in the filter) as a second guard.
- A single server instance is assumed (Render free tier). On boot, `in_progress` and `paused` attempts are loaded from the DB and their runtimes rebuilt. A paused attempt whose grace period has run out is ended early.
- **The only way attempt data reaches a client** is `toPlayerView(attempt, role)` in `services/attemptView.js`. Snapshot, unlock and result payloads all go through it. A unit test serializes its output and asserts that no answer, accepted answer, explanation, or other role's clue appears (NFR-1).
- Socket rooms: `attempt:<id>` for the 2 players (NFR-4); `leaderboard:<challengeId>` is read-only.
- Scoring is pure functions in `services/scoring.js`: `levelPoints({ activeMs, wrongCount, hintUsed })`, `completionBonus(remainingMs)`, `starsFor({ total, levelsCleared })`, `rankCompare(a, b)` (§7.3, §7.8). Phase 2 writes them test-first, with the §7.3 worked example (180 s, 1 wrong, no hint → 70) as a fixture.
- Answer normalization is `normalizeAnswer(text, kind)` in `services/answers.js`, where `kind` is `'word' | 'code' | 'list'` (§6.4).

**Level engine (Phase 3)**
- Each mechanic's generator lives in `generators/<mechanic>.js` and has the signature `generate({ params, rng, context }) → { clueA, clueB, answer, acceptedAnswers, answerKind, reward, explanation }`. A clue is `{ type: 'text'|'tokens'|'symbols'|'table'|'grid'|'strip', data }` (§6.3).
- `rng` is a seeded PRNG (mulberry32) created by `createRng(\`${seed}:${order}:${retry}\`)`, so `(seed, templates)` always regenerates the same level set (§6.1 step 2).
- `generateLevelSet(templates, seed)` runs the generators in order, threads `context` (earlier answers and rewards), validates each level (§6.1 step 4), retries up to 20 times, then falls back to `template.fallback`.
- Phase 2's fixed Cyber Heist values become the Cyber Heist templates' `fallback` in Phase 3.

**Leaderboards (Phase 4).** These are aggregation queries on `attempts` sorted by §7.3. They are never stored (§9.1).

**Rules each phase plan must carry.** TEAM-7 (no membership changes while an attempt is in progress) is enforced in `teamService` once attempts exist (Phase 3). CHAL-6's "replace the partner before the attempt starts" is checked in the same place.
